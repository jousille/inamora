## 📁 Карта файлов — что за что отвечает

| Файл | Роль | Что трогать |
| --- | --- | --- |
| `index.html` | Точка входа, подключает все скрипты и стили | Только при добавлении новых экранов |
| `manifest.json` | PWA-манифест: иконки, название, тема | Имя приложения, цвета |
| `sw.js` | Service Worker: кэширует файлы для офлайн-работы | Константа `CACHE` при каждом обновлении |
| `css/style.css` | Все стили приложения | Визуальные правки |
| `js/auth.js` | Авторизация: проверка токена (статический список или Supabase) | Список `VALID_TOKENS` при ручном методе |
| `js/db.js` | Работа с localStorage: хранение данных планера | Редко — только при добавлении новых типов данных |
| `js/app.js` | Главный роутер: инициализация, навигация между экранами | При добавлении новых экранов |
| `js/day.js` | Экран «День»: ввод энергии, доноры/вампиры | Логика дневного экрана |
| `js/week.js` | Экран «Неделя»: сводка за 7 дней | Логика недельного экрана |
| `js/month.js` | Экран «Месяц»: архив и статистика | Логика месячного экрана |
| `js/profile.js` | Экран «Профиль»: токен, экспорт/импорт данных | Логика профиля |
| `bot.py` | Telegram-бот: выдача токенов, интеграция с lava.top | Логика бота, команды |
| `requirements.txt` | Python-зависимости для бота | При добавлении новых библиотек |

**Структура localStorage** (ключи для каждого пользователя):

```
planer_session              — активная сессия (token + startDate)
planer_{token}_m{N}_{type}_{week}_{day}  — данные дня
  type: energy | donor | vampire | top
```

## 🔄 Обновление версии PWA

При любом изменении файлов планера пользователи видят старую версию из кэша — пока не сменить `CACHE`.

### Шаги обновления

1. Изменить нужные файлы (css, js, html)
2. Открыть `sw.js` и поменять номер кэша:

```js
// было:
const CACHE = 'planer-v1';
// стало:
const CACHE = 'planer-v2';
```

3. Залить все изменённые файлы на GitHub (commit + push в `main`)
4. Подождать 1–2 минуты — GitHub Pages автоматически пересоберёт сайт
5. Пользователь при открытии PWA увидит новый Service Worker и загрузит обновление

> **Важно**: если не поменять `CACHE`, пользователи будут видеть старый файл из кэша даже после заливки новых файлов.

### Последовательность номеров: `v1` → `v2` → `v3` … не сбрасывать, каждое обновление +1.

### Обновление APK / AAB

После изменений в коде React Native соберить новый бинарник через EAS Build (см. раздел «Сборка»). Данные пользователей в localStorage не затрагиваются обновлением приложения.

## 🔑 Токены — выдача доступа

### Метод  1: Статичный (в коде)

Просто, но требует перезаливки файла при каждом новом токене.

1. Открыть `js/auth.js`
2. Добавить новый токен:

```js
const VALID_TOKENS = {
  'INAMORA-DEMO':  { expires: null },
  'INAMORA-XXXXX': { expires: null },        // бессрочный
  'INAMORA-YYYYY': { expires: '2025-12-31' }, // с датой истечения
};
```

3. Обновить `CACHE` в `sw.js` и запустить deploy

### Метод 2: Через Supabase (рекомендуется)

Токен хранится в базе, код перезаливать не нужно.

**Структура таблицы `tokens` в Supabase:**

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | int8 (PK) | Авто-инкремент |
| `token` | text | Уникальный код |
| `used` | bool | Активирован |
| `expires_at` | timestamp | null = бессрочный |
| `user_id` | text | Telegram user\_id (null до активации) |
| `created_at` | timestamp | Авто |

**Выдать токен вручную** (через Supabase Table Editor):

1. Открыть проект на [supabase.com](https://supabase.com)
2. Table Editor → таблица `tokens` → Insert row
3. `token` = `INAMORA-XXXXX`, `used` = false

**Выдать токен через бота** — команда `/addtoken`:

```
/addtoken INAMORA-XXXXX
```

Бот запишет токен в Supabase и ответит подтверждением. Команда `/token` — автоматически создаёт случайный токен формата `INAMORA-XXXXXX`.

## 🤖 Телеграм-бот + Supabase

### Первая установка на Railway

1. Перейди на [railway.app](https://railway.app) → New Project → Deploy from GitHub
2. Подключи репозиторий с `bot.py`
3. Добавь переменные среды (Variables):

| Переменная | Где взять |
| --- | --- |
| `BOT_TOKEN` | @BotFather → создать бота |
| `ADMIN_CHAT_ID` | свой Telegram ID (через @userinfobot) |
| `SUPABASE_URL` | Supabase → Settings → API → Project URL |
| `SUPABASE_SERVICE_KEY` | Supabase → Settings → API → service\_role (secret) |
| `APP_URL` | URL планера, напр. `https://jousille.github.io/planer/` |
| `PRODUCT_URL` | Ссылка на страницу продукта |

4. Railway деплойтит бот автоматически

### Команды бота

| Команда | Действие | Доступ |
| --- | --- | --- |
| `/start` | Приветствие и инструкция | все |
| `/token` | Сгенерировать уникальный токен | только admin |
| `/addtoken XXX` | Добавить свой токен в Supabase | только admin |
| `/stats` | Статистика токенов | только admin |
| `/unlink` | Отвязать токен от Telegram ID | все |

### Обновление бота

1. Изменить `bot.py` в репозитории
2. Сделать commit + push
3. Railway автоматически перезапустит бот

> Переменные среды на Railway сохраняются между деплоямами, добавлять их повторно не нужно.

## 🤖 Сборка Android APK

### Что нужно

- Node.js и npm
- Expo CLI: `npm install -g expo-cli eas-cli`
- Аккаунт на [expo.dev](https://expo.dev)
- Проект в `expo.dev` (создаётся автоматически при первом `eas build`)

### Профили сборки в `eas.json`

```json
{
  "build": {
    "preview": {
      "android": { "buildType": "apk" }
    },
    "production": {
      "android": { "buildType": "app-bundle" }
    }
  }
}
```

> `preview` → `.apk` (установка напрямую). `production` → `.aab` (для Google Play).

### Шаги сборки APK

1. Открыть терминал в папке проекта
2. `eas login` — войти в аккаунт Expo
3. `eas build -p android --profile preview`
4. EAS соберёт APK на своих серверах (\~10–15 мин)
5. Ссылка на скачивание появится в терминале и на [expo.dev/accounts](https://expo.dev/accounts)
6. Скачать APK и установить на тестовый телефон

### Установка APK на Android

1. Передать APK на телефон (через мессенджер или файловый менеджер)
2. Зайти в Настройки → Безопасность → Установка неизвестных приложений → Разрешить
3. Открыть APK-файл → Установить

### Сборка AAB для Google Play

Заменить `--profile preview` на `--profile production`:

```
eas build -p android --profile production
```

Результат — `.aab` файл для загрузки в Google Play Console.

## 🍎 Сборка iOS (TestFlight / App Store)

### Что нужно дополнительно

- Подписка Apple Developer ($99/год) — без неё сдать в App Store нельзя
- Mac с Xcode (EAS собирает в облаке, Mac не нужен)
- Bundle ID в `app.json`: `"bundleIdentifier": "com.inamora.planer"`

### Шаги сборки iOS

1. Зарегистрироваться на [developer.apple.com](https://developer.apple.com) (индивидуальная подписка $99)
2. В терминале: `eas build -p ios --profile production`
3. EAS запросит Apple ID и создаст сертификаты автоматически
4. Сборка займёт \~20–40 мин
5. Перейти в [App Store Connect](https://appstoreconnect.apple.com) → TestFlight
6. Добавить тестеров через TestFlight → они получат ссылку для установки

### До покупки Apple Developer

**Самый простой способ** — добавить iOS PWA на экран через Safari:

1. Открыть `jousille.github.io/planer` в Safari на iPhone
2. Нажать «Поделить» (кнопка со стрелкой вверх)
3. «На экран «Домой»»

Приложение будет выглядеть как нативное без загрузки в App Store и бесплатно.

## ⚡ Шпаргалка: что делать, если…

| Ситуация | Действие |
| --- | --- |
| Изменила `style.css` или `js/*.js` | Изменить `CACHE` в `sw.js` + push |
| Добавить новый экран | Отредактировать `app.js` + `index.html` + изменить `CACHE` |
| Выдать токен покупателю | `/token` в боте (авто) или `/addtoken XXX` (свой) |
| Пользователь не может войти | Проверить токен в таблице `tokens` в Supabase |
| Обновить APK | `eas build -p android --profile preview` |
| Обновить бота | Push в `main` — Railway перезапустит сам |
| Данные пользователя не сохраняются | Данные в localStorage — попроси экспорт в Профиле |
| iOS без App Store | Safari → Поделиться → На экран «Домой» |
